# Библиотека шаблонов и Model Space для PDF → DWG

## Цель

Преобразовать векторный PDF в один редактируемый DWG без пользовательских
Layouts и Viewport. Для стандартных листов ГОСТ конвертер заменяет исходную
рамку проверенным шаблоном из пользовательского DWG 1:1. Семантические
обозначения создаются нативными объектами AutoCAD или именованными блоками с
редактируемыми атрибутами.

Это решение предназначено для будущего сайта: сервер конвертации не требует
установленного AutoCAD после первоначального извлечения библиотеки.

## Входные материалы и границы

- Исходник шаблонов: `Пример шаблонов.dwg`, подготовленный пользователем в
  масштабе 1:1.
- PDF остаётся только векторным в этой версии. Сканированные документы не
  входят в объём работы.
- Паттерн и масштаб штриховки могут отличаться от шаблонов. Они распознаются
  по исходной геометрии PDF и создаются нативным `HATCH` только при достаточной
  уверенности.
- Стандартные форматы включают A0–A4 в альбомной и книжной ориентации.
  Нестандартная страница сохраняет свою исходную рамку и геометрию.

## Решение

### Одноразовое извлечение библиотеки

Плагин AutoCAD получает команду `TEYPDFEXPORTTEMPLATES`. Она открывает
активный пользовательский DWG и сохраняет нейтральный манифест библиотеки.
Манифест содержит определения блоков, геометрию, слои, стили текста и размеров,
атрибуты, вставки, динамические свойства, фактические классы AutoCAD и границы
элементов. Экспорт всегда только читает исходный DWG и не изменяет его.

AutoCAD API используется потому, что независимый DWG-читатель может не увидеть
СПДС-, proxy- или dynamic-объекты, которые визуально присутствуют в файле.
Экспорт пишет также диагностический список не поддержанных объектов, чтобы они
не исчезали молча.

После проверки пользовательского экспорта проект формирует переносимую
внутреннюю библиотеку. Обычный серверный путь PDF → DWG использует только её;
никакой `PDFIMPORT`, ручная автоматизация и лицензия AutoCAD на сервере не
нужны.

### Результат конвертации

DWG содержит только Model Space и исходную модель конвертера. Конвертер не
создаёт новых Layout, viewport или Paper Space-содержимого. Страницы одного PDF
раскладываются в Model Space без пересечения, каждая получает служебный
идентификатор страницы в слоях и отчёте.

При подтверждённом стандартном формате конвертер:

1. исключает исходную PDF-рамку и исходную основную надпись из экспортируемой
   геометрии;
2. вставляет соответствующий блок рамки 1:1;
3. извлекает распознанный текст штампа и назначает его атрибутам вставки;
4. оставляет неоднозначный текст штампа отдельным редактируемым текстом на
   слое проверки.

При нестандартном формате ни рамка, ни штамп не подменяются.

### Семантические объекты

| Семантика PDF | Результат в DWG |
| --- | --- |
| Ось | именованный блок `TEY_AXIS` с атрибутом марки |
| Уровень | именованный блок `TEY_LEVEL` с атрибутом отметки |
| Обрыв | именованный блок `TEY_BREAK`, геометрия блока редактируема |
| Разрез, фасад, узел | именованный блок с атрибутами номера и листа |
| Выноска | нативный `MLEADER` с редактируемым содержимым |
| Размер | нативный `DIMENSION` |
| Заливка/штриховка | нативный `HATCH` с редактируемой границей |

Служебные линии осей, отметок, выносок, марок узлов, разрезов и обрывов получают
вес `0,09 мм` (`LineWeight009`). Шаблон сохраняет пользовательские стили, когда
они совместимы с целевым DWG. Иначе применяется документированный стиль
совместимости, но текст и геометрия остаются редактируемыми.

### Уверенность и безопасность данных

Шаблон или нативный объект заменяет исходную геометрию только после
высокоуверенного распознавания формы, подписи, положения и масштаба. Если
доказательств недостаточно, исходные линии, полилинии и текст сохраняются на
слое `TEY_REVIEW_*` с причиной в отчёте. Конвертер не удаляет сомнительные
детали и не подменяет их "похожим" символом.

### Текст

Текст PDF собирается в слова, строки и многострочные области по базовой линии,
высоте, повороту и межсимвольным расстояниям. Выход — `DBText` для коротких
подписей и `MText` для абзацев и ячеек. Масштаб текста определяется в
миллиметрах, межстрочное расстояние сохраняется, а перекрытия фиксируются в
диагностике. Текст атрибутов шаблонов заменяется значениями из PDF только после
проверки привязки к ячейке штампа.

## Контракты и артефакты

- `TemplateLibraryManifest` — версионированный JSON, экспортированный AutoCAD
  из конкретного DWG-источника.
- `TemplateLibrary` — независимая для серверного конвертера модель блоков,
  атрибутов и стандартных листов.
- `TemplateRecognitionResult` — формат листа, выбранный шаблон, заполненные
  атрибуты, уверенность и причины отказа.
- Отчёт конвертации содержит число заменённых рамок, вставленных семантических
  объектов, объектов `TEY_REVIEW_*`, Layout и Viewport (для этой версии оба
  значения обязаны быть нулевыми).

## Проверка

1. Тесты экспортёра проверяют, что исходный DWG не изменяется, а манифест
   содержит блоки, атрибуты, стили и не поддержанные классы.
2. Тесты выбора шаблонов проверяют A0–A4 в обеих ориентациях и отказ для
   нестандартного размера.
3. Тесты записи проверяют Model Space-only DWG: Layout = 0, Viewport = 0,
   вставка рамки 1:1 и редактируемые атрибуты.
4. Тесты семантики проверяют `MLEADER`, `DIMENSION`, `HATCH`, блоки и
   `LineWeight009`.
5. Приёмочный пакет преобразует тестовый A3 и 51-страничный PDF, выполняет
   read-back и выдаёт AutoCAD-скрипт для ручного запуска пользователем.

## Не входит в этот этап

- OCR/распознавание сканов;
- полноценная поддержка всех сторонних СПДС proxy-объектов на сервере;
- автоматическое исправление сомнительных элементов без сохранения источника;
- веб-интерфейс, учётные записи и биллинг.
