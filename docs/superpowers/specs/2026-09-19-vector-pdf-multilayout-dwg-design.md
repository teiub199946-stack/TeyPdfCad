# Векторный PDF → многолистовой DWG: проектное решение

## Цель

Создать независимое ядро конвертации для будущего сайта. Оно принимает
векторный многостраничный PDF и формирует один редактируемый DWG: один
`Layout` на страницу PDF и связанная геометрия в `Model Space`.

Первый релиз работает только с векторными PDF. Сканированные PDF и фотографии
будут поддержаны отдельным модулем распознавания после приёмки векторного пути.

## Принятые решения

- Результат одного PDF — один DWG, а не набор DWG-файлов.
- Для PDF с 51 страницей создаётся 51 Layout.
- Конвертер работает на сервере без автоматизации AutoCAD и без `PDFIMPORT`.
- PDF сначала разбирается в независимую внутреннюю модель документа, затем
  записывается в DWG. Веб-сайт не должен содержать логику распознавания.
- Точность важнее агрессивного распознавания: неоднозначный объект остаётся
  точной редактируемой геометрией, а не ошибочным `DIMENSION` или `MLEADER`.

## Документная модель и единицы

Документ состоит из упорядоченных страниц. У каждой страницы есть исходные
габариты, поворот, векторные примитивы, текст, графические стили и результаты
распознавания рамки, штампа, видовых областей и масштаба.

Координаты PDF переводятся в миллиметры по точному соотношению
`1 pt = 25,4 / 72 мм`. Размер страницы сохраняется фактическим. Форматы A0–A4
определяются как контрольные признаки, а не как повод растягивать нестандартный
лист. Рамка и штамп исходного PDF сохраняются по их реальным координатам.

## Структура создаваемого DWG

### Model Space

Model Space содержит нативную геометрию чертёжных областей, изолированную по
страницам и видам. При надёжно определённых границах видового экрана и масштабе
геометрия нормализуется к модельным единицам. Геометрия разных листов не
смешивается: используются отдельные именованные наборы/блоки и слои с
идентификатором страницы.

### Layout

Для каждой страницы создаётся `Лист-001`, `Лист-002` и так далее. Layout имеет
фактический размер PDF-страницы в миллиметрах. В нём остаются рамка, штамп,
листовые примечания, размеры и выноски. Для подтверждённых чертёжных областей
создаются Viewport, указывающие на соответствующую геометрию Model Space с
распознанным масштабом.

Если источник не даёт достаточных оснований надёжно восстановить масштаб или
границу вида, объект сохраняется в Paper Space в масштабе бумаги 1:1; отчёт
явно фиксирует это решение. Конвертер не меняет масштаб по догадке.

## Объекты и стили

| Источник PDF | Результат DWG |
| --- | --- |
| Прямая | `LINE` |
| Контур или ломаная | `LWPOLYLINE` |
| Дуга и окружность | `ARC`, `CIRCLE` |
| Текст | `TEXT` или `MTEXT` |
| Распознанный размер | нативный `DIMENSION` |
| Распознанная выноска | `MLEADER` или `LEADER` |
| Распознанная штриховка | `HATCH`; при неоднозначности — линии |

Для каждого примитива сохраняются слой, цвет, толщина линии, прозрачность и
тип линии. Штриховые и штрихпунктирные линии получают DWG-тип линии и масштаб,
при котором рисунок штриха соответствует листу. Оси получают отдельный слой и
осевой тип линии.

Размеры, выноски и оси распознаются по геометрии, стрелкам, тексту и их
пространственной связи. Семантический объект создаётся только после прохождения
порога уверенности. Иначе переносятся исходные линии, стрелки и текст.

## Слои и изоляция

Конвертер сохраняет слои PDF, когда эта информация доступна. Созданные
служебные слои имеют зарезервированный префикс и отделяют рамки, штампы,
аннотации, оси, геометрию модели и объекты, оставленные в Paper Space. Это
позволяет редактировать и проверять слои без затрагивания объектов других
страниц.

## Серверная граница

Ядро предоставляет операцию: входной векторный PDF → DWG и отчёт. Будущий сайт
отвечает только за загрузку, хранение, очередь, статус и выдачу результата.
Такое разделение позволяет масштабировать серверные задания и позднее добавить
сканирование без изменения правил для векторных PDF.

## Отчёт и ошибки

Каждое задание создаёт машиночитаемый и человекочитаемый отчёт. В нём есть:

- число страниц и созданных Layout;
- размер и определённый формат каждого листа;
- число объектов по типам;
- число нативных размеров, выносок, Viewport и объектов Model Space;
- объекты, оставленные геометрией из-за низкой уверенности;
- предупреждения и ошибки с номером страницы.

Повреждённый или невекторный PDF не выдаётся как успешный DWG. При частичной
обработке готовый DWG и отчёт явно маркируются как неполные.

## Приёмка первого большого блока

Для приёмки готовится единый пакет AutoCAD-тестирования, а не серия мелких
ручных проверок. Пакет содержит собранный конвертер, сценарий запуска, DWG,
отчёт, журналы и автоматические проверки Layout, листовых размеров, Model
Space, Viewport, слоёв, типов линий, размеров и выносок.

Контрольные материалы включают одно-страничный A3 PDF и 51-страничный PDF с
разными типами листов и инженерной графикой. Критерий успеха: один DWG с
Layout для всех обработанных страниц, без наложения листов, с сохранёнными
габаритами, редактируемой геометрией и прозрачным отчётом о границах
распознавания.

## Не входит в первый блок

- распознавание растровых сканов и фотографий;
- пользовательский веб-интерфейс, биллинг и учётные записи;
- безусловное восстановление семантики там, где PDF не содержит достаточных
  признаков;
- ручная автоматизация AutoCAD или зависимость от установленного AutoCAD.
