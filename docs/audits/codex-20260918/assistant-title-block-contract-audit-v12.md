# TeyPdfCad title-block contract audit v12

Дата аудита: 2026-09-18

Область: read-only проверка текущего checkout `TeyPdfCad-restored` по контракту редактируемого A3 title block. Сборка и runtime не запускались. Исходники и тесты не изменялись; создан только этот отчет.

## Подтверждено

- A3-модель и детектор формата существуют в Core. `StandardSheetDetector.Detect` принимает ширину/высоту страницы, проверяет конечность и положительность значений, использует допуск по умолчанию 2 mm и распознает A3 landscape/portrait как 420 x 297 или 297 x 420 mm ([StandardSheetDetector.cs:3-29](src/TeyPdfCad.Core/Sheets/StandardSheetDetector.cs:3)). Текущий контракт сохраняет измеренные `WidthMm`/`HeightMm`, формат и ориентацию в `SheetFormatDetection`/`SheetMetadata` ([SheetFormat.cs:16-23](src/TeyPdfCad.Core/Sheets/SheetFormat.cs:16), [SheetMetadata.cs:3-9](src/TeyPdfCad.Core/Sheets/SheetMetadata.cs:3)).
- Добавлен явный `SheetPageBounds` контракт: он хранит `MinX`, `MinY`, физические `WidthMm`/`HeightMm`, units и вычисляемые `MaxX`/`MaxY`; `SheetMetadata.PageBounds` остается optional ([SheetPageBounds.cs:3-12](src/TeyPdfCad.Core/Sheets/SheetPageBounds.cs:3), [SheetMetadata.cs:3-10](src/TeyPdfCad.Core/Sheets/SheetMetadata.cs:3)). Это позволяет отличать origin/границы страницы от экстентов импортированной геометрии.
- `PrimitiveScene` может нести необязательные `Sheet` и `TitleBlock` ([PrimitiveScene.cs:5-10](src/TeyPdfCad.Core/Primitives/PrimitiveScene.cs:5)). Это совместимо с существующими сценами: поля nullable.
- Core-модель title block включает регион, редактируемые поля, тип поля, положение, высоту, поворот и source provenance ([TitleBlockRegion.cs:5-35](src/TeyPdfCad.Core/Sheets/TitleBlockRegion.cs:5)). Поддерживаемые семантические типы перечислены в `TitleBlockFieldKind` ([TitleBlockFieldKind.cs:3-17](src/TeyPdfCad.Core/Sheets/TitleBlockFieldKind.cs:3)).
- `TitleBlockDetector` fail-closed при отсутствии текста или менее двух исходных line segments. Нераспознанный текст сохраняется с `TitleBlockFieldKind.Unknown`, исходным значением и provenance; значения drawing number/date/approval не выдумываются ([TitleBlockDetector.cs:7-18](src/TeyPdfCad.Core/Sheets/TitleBlockDetector.cs:7), [TitleBlockDetector.cs:35-64](src/TeyPdfCad.Core/Sheets/TitleBlockDetector.cs:35)).
- Fixture formatter сериализует `sheet`, optional `pageBounds` и `titleBlock` в схему `TeyPdfCad.PrimitiveScene.v1`, включая origin, units, регион, source IDs, поля и неизвестную семантику ([PrimitiveSceneFixtureFormatter.cs:8-12](src/TeyPdfCad.AutoCAD/PrimitiveSceneFixtureFormatter.cs:8), [PrimitiveSceneFixtureFormatter.cs:68-145](src/TeyPdfCad.AutoCAD/PrimitiveSceneFixtureFormatter.cs:68)). Отдельные тесты покрывают A3 metadata, отсутствие выдуманной семантики и page-origin detector contract ([PrimitiveSceneFixtureFormatterTests.cs:12-47](tests/TeyPdfCad.AutoCAD.Tests/PrimitiveSceneFixtureFormatterTests.cs:12), [TitleBlockDetectorTests.cs:47-64](tests/TeyPdfCad.Tests/TitleBlockDetectorTests.cs:47)).
- Core unit tests проверяют A3 landscape/portrait, unknown format и минимальные условия кандидата title block ([SheetFormatDetectorTests.cs:6-33](tests/TeyPdfCad.Tests/SheetFormatDetectorTests.cs:6), [TitleBlockDetectorTests.cs:8-44](tests/TeyPdfCad.Tests/TitleBlockDetectorTests.cs:8)). Это статические/unit evidence, не доказательство создания DWG.
- Проектная спецификация правильно фиксирует целевой результат: A3 Paper Space/Layout, редактируемая геометрия рамки, именованный AutoCAD block, editable DBText/MText или attributes, отсутствие fabricated values ([SHEET_FIDELITY_SPEC.md:26-44](docs/SHEET_FIDELITY_SPEC.md:26)). README прямо указывает, что Layout creation и native title-block block writing еще являются следующим adapter step ([README.md:65-67](README.md:65)).

## Пробелы

- `AutoCadPrimitiveReader.Read` создает пустой `PrimitiveScene`, наполняет только `Lines` и `Texts` и возвращает его без присвоения `Sheet` или `TitleBlock` ([AutoCadPrimitiveReader.cs:9-54](src/TeyPdfCad.AutoCAD/AutoCadPrimitiveReader.cs:9)). Новый `SheetPageBounds` контракт существует в Core, но текущий AutoCAD adapter по-прежнему не извлекает PDF page bounds/units и не вызывает `StandardSheetDetector` или `TitleBlockDetector`.
- Рабочий путь реконструкции не использует title-block contract. `ReconstructionCommands.Reconstruct` читает сцену и сразу передает ее в `SemanticReconstructionEngine`, затем пишет только native dimensions в `database.CurrentSpaceId` ([ReconstructionCommands.cs:150-188](src/TeyPdfCad.AutoCAD/ReconstructionCommands.cs:150)). После validation выполняются только optional erase source geometry, units и commit ([ReconstructionCommands.cs:190-220](src/TeyPdfCad.AutoCAD/ReconstructionCommands.cs:190)). Вызовов detector, LayoutManager, Paper Space, BlockTableRecord для блока, `BlockReference`, `AttributeDefinition` или `AttributeReference` нет.
- В checkout нет реализации writer-а рамки/title block: поиск AutoCAD integration points находит только текущую запись dimensions через `NativeDimensionWriter` ([NativeDimensionWriter.cs:8-53](src/TeyPdfCad.AutoCAD/NativeDimensionWriter.cs:8)). Поэтому serialized candidate не превращается в редактируемый DWG block.
- Текущий Core contract не содержит списка title-block line primitives или их геометрии. `TitleBlockRegion` хранит только bounding box и source IDs, а поля хранят только текстовые свойства ([TitleBlockRegion.cs:5-29](src/TeyPdfCad.Core/Sheets/TitleBlockRegion.cs:5)). Спецификация требует хранить title-block lines/texts с provenance, но линии остаются только в общем `PrimitiveScene.Lines`; отдельной связи с accepted region нет.
- `TitleBlockDetector` теперь использует явные `PageBounds.MinY` и `PageBounds.MaxX`, когда они переданы, и только иначе откатывается к `minY`/`maxX` scene points ([TitleBlockDetector.cs:20-31](src/TeyPdfCad.Core/Sheets/TitleBlockDetector.cs:20)). Это устраняет прежнюю ошибку origin для импортированной страницы, но не превращает эвристику правого нижнего угла в page-aware анализ рамки/табличной сетки. Проверка line segments по-прежнему считает линию подходящей, если в регионе находится хотя бы один endpoint ([TitleBlockDetector.cs:46-57](src/TeyPdfCad.Core/Sheets/TitleBlockDetector.cs:46)); сегмент, пересекающий область, но имеющий endpoints снаружи, будет пропущен.
- `SheetMetadata` теперь имеет optional `PageBounds`, но контракт все еще не хранит source page ID или provenance; `Units` представлены строкой в `SheetPageBounds` и не валидируются самим record ([SheetPageBounds.cs:3-12](src/TeyPdfCad.Core/Sheets/SheetPageBounds.cs:3)). Любой вызывающий код все еще может вручную выставить размеры/origin без доказанной связи с PDF, пока upstream reader не предоставит page metadata.
- Existing tests проверяют модель/JSON, но отсутствуют endpoint/AutoCAD runtime tests, которые подтверждают A3 Layout, editable frame, named block, editable fields, lineweight distinction, save/reopen DWG. Acceptance spec сама требует реальный A3 vector PDF и независимую проверку этих свойств ([SHEET_FIDELITY_SPEC.md:59-76](docs/SHEET_FIDELITY_SPEC.md:59)).

## Конкретные точки интеграции

1. **Извлечение страницы и Core enrichment.** После получения прямых PDF page bounds (или отдельного page metadata input) создать `SheetPageBounds`, присвоить его `SheetMetadata.PageBounds`, а формат получить через `StandardSheetDetector.Detect`; measured bounds и detected format должны оставаться отдельными данными. В текущем временном AutoCAD-пути ближайшая точка передачи сцены находится сразу после `new AutoCadPrimitiveReader().Read(...)` в `ReconstructionCommands.cs:150-154`; новый контракт не меняет того, что без page metadata этот путь должен оставаться `Unknown`, а не угадывать A3.
2. **Кандидат title block.** После того как `scene.Sheet` и корректные page coordinates установлены, вызвать `TitleBlockDetector.Detect(scene, scene.Sheet)` рядом с `ReconstructionCommands.cs:152-156`. Результат присвоить только как candidate (`scene.TitleBlock`), не удаляя source primitives до успешной нативной записи и validation.
3. **Расширение контракта геометрии.** Перед writer-ом требуется либо добавить в `TitleBlockMetadata` отобранные line/text primitives, либо передавать writer-у `scene` плюс accepted `Region`; иначе writer не имеет точной геометрии сетки штампа. Сохранять `Unknown` fields и source IDs; semantic attributes создавать только для доказанно распознанных `TitleBlockFieldKind`.
4. **Paper Space/Layout writer.** Интеграцию размещать в adapter transaction рядом с текущим `currentSpace`/dimension write (`ReconstructionCommands.cs:182-209`). Writer должен получить `Database`, `Transaction`, `SheetMetadata`, accepted region и primitives, найти/создать Layout с A3 paper size/orientation, записать рамку как native Line/Polyline в Paper Space и не смешивать ее с Model Space.
5. **Named block и editable text.** В том же adapter layer создать `BlockTableRecord` с детерминированным именем, добавить line entities, а `Unknown` поля записывать в DBText/MText. `AttributeDefinition`/`AttributeReference` использовать только для семантически подтвержденных полей. Вставить `BlockReference` в Layout/Paper Space и оставить explode/edit behavior стандартным AutoCAD.
6. **Formatter/evidence.** `PrimitiveSceneFixtureFormatter.Format` уже является read-only evidence point и теперь включает optional `pageBounds` (`PrimitiveSceneFixtureFormatter.cs:12-145`), но fixture JSON нельзя считать DWG acceptance. После writer-а добавить отдельный runtime command/report, который подтверждает layout name/size, block name, entity types, field text/attributes, lineweights и saved-DWG reopen.
7. **Regression gates.** Расширить Core tests вокруг page bounds/units and region edge cases, затем AutoCAD adapter tests around writer construction. Final gate remains the real A3 vector PDF with Cyrillic text, multiple lineweights and a reopened DWG as required by `SHEET_FIDELITY_SPEC.md:61-76`.

## Риски и границы

- Этот аудит не запускал build, unit tests или AutoCAD. Все подтверждения выше основаны на source inspection; они не доказывают runtime DWG output.
- Core detector сейчас определяет лишь candidate region. Принятие его результата как реального штампа может захватить рамку/служебную геометрию или пропустить штамп, если он не находится в правом нижнем углу или имеет другой масштаб.
- PDFIMPORT может не раскрывать исходные PDF line widths. `AutoCadPrimitiveReader` читает AutoCAD entity `LineWeight` и переводит положительное значение из hundredths-of-mm в mm ([AutoCadPrimitiveReader.cs:115-119](src/TeyPdfCad.AutoCAD/AutoCadPrimitiveReader.cs:115)); это не равно доказанному исходному PDF stroke width. Точное сохранение толщин остается зависимым от Direct PDF reader и реального A3 fixture.
- При `preserveSourceGeometry=false` существующий reconstruction path удаляет выбранные source entities после dimension validation ([ReconstructionCommands.cs:202-207](src/TeyPdfCad.AutoCAD/ReconstructionCommands.cs:202)). До появления отдельного title-block writer-а нельзя считать такое удаление безопасным для редактируемого штампа.
- Core Console/runtime gate остается отдельной границей: наличие `sheet`/`titleBlock` в JSON или unit test не доказывает запуск AutoCAD, создание Layout/BlockReference или reopenable DWG.

## Addendum: title-block line geometry

- В текущем checkout `TitleBlockMetadata` дополнен optional `Lines` (`IReadOnlyList<LinePrimitive>`), а `TitleBlockDetector` теперь выбирает line primitives региона и возвращает их вместе с candidate metadata ([TitleBlockRegion.cs:33-39](src/TeyPdfCad.Core/Sheets/TitleBlockRegion.cs:33), [TitleBlockDetector.cs:54-69](src/TeyPdfCad.Core/Sheets/TitleBlockDetector.cs:54)). Это закрывает прежний Core contract gap по хранению геометрии линий штампа с их исходными properties/provenance.
- `PrimitiveSceneFixtureFormatter` сериализует `titleBlock.lines` после fields, включая исходные endpoints, layer, stroke width при наличии и source IDs ([PrimitiveSceneFixtureFormatter.cs:107-150](src/TeyPdfCad.AutoCAD/PrimitiveSceneFixtureFormatter.cs:107)). AutoCAD formatter test проверяет наличие serialized line geometry ([PrimitiveSceneFixtureFormatterTests.cs:25-53](tests/TeyPdfCad.AutoCAD.Tests/PrimitiveSceneFixtureFormatterTests.cs:25)).
- AutoCAD writer gap остается открытым: нет реализации создания A3 Layout/Paper Space, рамки, named `BlockTableRecord`/`BlockReference` и editable DBText/MText/attributes из `TitleBlockMetadata.Lines`/`Fields`. Поэтому `titleBlock.lines` в fixture JSON является только source/contract evidence и не доказывает редактируемый title block в DWG. Сборка и AutoCAD runtime в рамках addendum не запускались.
